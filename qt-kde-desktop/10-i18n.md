# 10 — Internationalisation

KDE translates with **gettext** (`.po` → `.mo`), domain = app name, functions `i18n()`,
`i18nc()` (with context), `i18np()` (plural), `i18ncp()`. Use the same for Python apps:
one mechanism for QML and Python, the same tooling as KDE translators, and real
translations for kirigami-addons' own strings.

## Who translates what

| Strings | Mechanism | Catalog |
| --- | --- | --- |
| Your QML | `i18n("Open %1", name)` | `myapp` domain, your `po/` |
| Your Python | `tr("…")`, `trp("…", "…", n)` (same catalog) | `myapp` |
| Your C++ | `i18n(...)` with `TRANSLATION_DOMAIN="myapp"` | `myapp` |
| kirigami-addons (FormCard, About page) | they call `i18nd("kirigami-addons6", …)` | system `/usr/share/locale/*/LC_MESSAGES/kirigami-addons6.mo` |
| Kirigami itself | loads its own Qt `.qm` (`libkirigami6_qt.qm`) automatically | — |
| Qt's standard strings (dialog buttons) | `QTranslator` for `qt_<lang>.qm` from `QLibraryInfo.TranslationsPath` | system |

## Python: a gettext-backed `i18n()` context

KI18n has no Python binding, and `import org.kde.ki18n` from a Python app gives a **null
singleton** (verified: "callback function returns a null pointer") because C++
`setupLocalizedContext` creates it. So provide the functions as a context object —
[`qt/i18n.py`](templates/python-kirigami/src/myapp/qt/i18n.py):

```python
class LocalizedContext(QObject):
    def _t(self, domain, context, text, plural, args):
        catalog = self._c.get(domain)                       # gettext.translation(..., fallback=True)
        if plural is None:
            out = catalog.pgettext(context, text) if context else catalog.gettext(text)
        elif context:
            out = catalog.npgettext(context, text, plural, _count(args))
        else:
            out = catalog.ngettext(text, plural, _count(args))
        return substitute(out, args)                        # KDE's %1..%n

    @_overloads(1)                                          # one Slot per arity 0..6
    def i18n(self, text, *args): return self._t(DOMAIN, None, text, None, args)
    @_overloads(2)
    def i18nd(self, domain, text, *args): return self._t(domain, None, text, None, args)
    # i18nc, i18np, i18ncp, i18ndc, i18ndp, i18ndcp likewise

engine.rootContext().setContextObject(LocalizedContext(Catalogs(languages(), app_localedir), engine))
```

- **Language** = the desktop's UI languages: `QLocale().uiLanguages()` (`pt-BR` → `pt_BR`,
  then `pt`), overridable with `LANGUAGE=pt_BR` for testing. Changing it needs a restart
  (the C++ `KLocalizedQmlContext` re-evaluates bindings live; this stand-in does not).
- **Lookup dirs**: the app's domain from `src/myapp/locale` in a checkout (compiled by
  `scripts/i18n.sh compile`), else `/usr/share/locale`; other domains from the system.
- KDE placeholders are `%1`…`%n` (not `{}`/`%s`); a whole float prints as an int; unknown
  placeholders stay. Plural selection uses the catalog's `Plural-Forms` with the first
  argument as `n`.
- Python strings: `tr("Copied %1", path)` / `trp("%1 file", "%1 files", n)` — the
  `xgettext` keywords cover them.
- Never build sentences from fragments (`tr("Copied") + " " + name`); give translators the
  whole sentence with placeholders, and context (`i18nc("@action:button", "Open")`) for
  short ambiguous words. Comments for translators: `// TRANSLATORS: …` above the call.
- Format numbers, sizes and dates with `QLocale()` (`formattedDataSize`, `toString`), not in
  the message.
- Do not translate log messages; do translate everything the user sees, including toasts
  built in Python and the About data.

## Workflow

[`scripts/i18n.sh`](templates/python-kirigami/scripts/i18n.sh):

```sh
scripts/i18n.sh extract        # xgettext → po/myapp.pot (Python as Python, QML as JavaScript)
scripts/i18n.sh new pt_BR      # msginit → po/pt_BR.po
scripts/i18n.sh update         # extract + msgmerge into every po/*.po, prints statistics
scripts/i18n.sh compile [DIR]  # msgfmt --check → DIR/<lang>/LC_MESSAGES/myapp.mo
```

Keywords: `-ki18n:1 -ki18nc:1c,2 -ki18np:1,2 -ki18ncp:1c,2,3 -ktr:1 -ktrp:1,2`.
`xgettext --language=JavaScript` extracts QML reliably (57 strings from the template,
contexts and plurals included). Packaging compiles into `/usr/share/locale` in `build()`;
the user installer into `~/.local/share/locale`. C++: `ki18n_install(po)` with KDE's
`po/<lang>/myapp.po` layout.

Translate the `.desktop` (`Name[pt_BR]=`, `Comment[pt_BR]=`, `Keywords[pt_BR]=`) and the
AppStream file (`<name xml:lang="pt-BR">`) too.

## Testing translations

The template tests that the QML window speaks pt_BR end-to-end (compile the `.po` into a
temp dir, point `DEV_LOCALEDIR` at it, `LANGUAGE=pt_BR`, assert the window title and a
drawer action), that kirigami-addons strings come from the system catalog, and that
plurals follow the catalog. Also try a long language (German) for truncation and an RTL
one (`LANGUAGE=ar`, `Qt.application.layoutDirection`) — Kirigami mirrors layouts.
